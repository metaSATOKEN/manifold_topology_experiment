# P0-0001 実装v2：JSON往復時の環境誤判定を修正

2026-10-20。ユーザーの不具合修正依頼に基づく追補。科学的仕様はv1のまま。モデル・入力・精度・抽出・指標・閾値・時間上限は変更しない。v1のソース・カード・受領ZIP・原観測は保持する。

## 観測済みの故障

run `7ec0f9a0ff0c` の失敗ZIPを受領。SHA-256 `7069b3138b9eca3c0d5ce78d46f2b3cc1d7c8b5a9711c8aa0c66ee99efec135c`、5,932,334 bytes、36収録ファイル。2文書・512 tokens・8抽出点の原観測はハッシュと構造を検証済み。残り2文書の推論・PCAは未到達。

起動時のpackages一覧はtupleを含み、JSON保存後はlistになる。v1は読込値とメモリ上の値を直接比較したため、同じGPU・ドライバ・依存でも不一致と判定した。受領した2つの環境記録の比較項目は完全一致し、tuple型を復元するとpackagesだけが不一致、JSON表現へ揃えると一致することをローカルで再現した。

## 修正の範囲

1. 環境比較をJSON往復で変わらない表現に統一する。実際に違うGPU・ドライバ・依存版は引き続き拒否し、差分の項目を報告する。
2. 配布元に固定したv1ハッシュだけを受け入れる移行経路を用意する。元のZIP・run・ソースは残し、新しいフォルダでv2へ移す。旧run manifestと旧ソースを履歴に保存し、run ID・科学的spec・文書ファイルとCOMMITは変えない。移行元ZIPのハッシュも記録する。ZIP内コードは実行しない。
3. 同じColab VMなら既存の隔離環境・モデルキャッシュを再利用する。再利用前後に固定版と環境契約を確認する。モデル設定の比較では保存場所だけを意味のない差分として除き、実際の設定差は拒否する。元の設定記録は残す。
4. 修正版の既定動作は再開。既知の失敗ZIPが同じVMにあれば選び、なければZIPアップロードへ進む。新規runは明示指定だけで開始する。
5. `torch_dtype` の非推奨警告は今回の停止原因ではない。科学処理を広げる修正は行わない。

## 修正前の予想と確認方法

- 受領した環境記録を使い、保存前tuple／保存後listの双方を同じ環境として受け入れる。
- GPU、driver、torch、依存版などを変えた対照は拒否する。
- 実際の失敗ZIPをv2へ移しても、2文書のraw・metadata・COMMITのハッシュが全て一致する。失敗・attempt・復元記録も残る。
- 元の環境が同じなら、ユーザーのColab再実行で2文書をスキップし、残り2文書を取得する。最終的に4文書・16点が揃う。過去のworker失敗1件を消さない。
- ローカルでは受領物と合成データで回帰検査し、モデル推論は行わない。GPUでの修正版完走はユーザー実行後まで未検証。

## 記録と限界

v1のP0は再開段階で失敗。原観測保存・checkpoint復元は部分的に確認できたが、P0全体は未完了。v1の26件の合成検査は環境契約のJSON往復をカバーしていなかった。この不足を台帳§7とFP標本に記録する。

配布物は `p0_v2/` に固定し、ハッシュは同フォルダのrelease manifestへ記録する。v1の科学的specをそのまま使うためexperiment IDは `pcgeom_p0_v1`、コード配布名とZIP接頭辞は `pcgeom_p0_v2`。修正版で新しいGPU推論を行うのはユーザー。次のモデル観測取得前にこの追補と実装を固定する。
