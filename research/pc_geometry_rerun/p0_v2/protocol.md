# P0-0001 v1 — 原観測・中断再開・ZIP往復の技術試験

2026-10-20。実装・配布の依頼に基づく固定仕様。リリース時にコード・入力・本文のハッシュを `p0_v1/release_manifest.json` に固定する。実行はユーザーがColabで行い、agentはモデルを実行しない。P1/P2の科学的仮説を判定する試験ではない。

## 1. 問いと対象

GPT-2の隠れ状態を抽出・保存し、プロセス終了後にZIPから復元して継続でき、同じ原観測からPC指標を再計算できるか。

- モデル／tokenizer：`openai-community/gpt2`、revision `607a30d783dfa663caf39e06633721c8d4cfcd7e`。公開safetensorsのみ、remote codeなし。
- 入力：今回作成する英語の人工テスト文章4本。各段落を3回連結し、特殊トークン追加なしで先頭256トークンを使用。短ければ失敗とし、別文書で補わない。paddingなし、batch 1。
- 4本は保存試験用fixtureであり、自然言語コーパスの代表標本・独立反復の証拠ではない。P1/P2の評価集合から除く。
- 点：1番目・6番目・12番目のTransformerブロック出力（残差加算後、最終LayerNorm前）、最終LayerNorm後の4箇所。12ブロック・隠れ次元768を要求する。
- 推論と保存：float32、eval/inference mode、TF32なし、eager attention、KV cacheなし。量子化・生成・学習は行わない。
- 1回の正常完走は文書4件のforward、16個の文書×抽出点。GPUの小さな行列演算診断は別計数。再試行はattemptとして残す。

## 2. 保存と計算

- 各文書：元テキスト、入力token ID・token表記・単体decode文字列・文字数・UTF-8バイト数、位置、mask、元logitの位置、現在tokenのsurprisalとそのtarget logit/logsumexp、4箇所の隠れ状態。
- 位置0のsurprisalはNaN、source indexは-1。位置t>=1はlogits[t-1]から算出し、cross entropyとの一致を診断する。
- PC分析：文書×抽出点ごとに中心化、NumPy float64の完全SVD。上位8成分の基底・score・平均、全特異値に対応する固有値、総分散を保存する。
- `R1=|corr(score1, norm)|`、`V1=lambda1/total_variance`、PC1〜8と位置・token単体decode文字数・surprisalの相関を記述的に保存。定数特徴はnull。PC符号は最大絶対成分を正にする。
- 分母の総分散は中心化行列の平方和/(N-1)。同じ文章内での記述に限り、held-out性能、品詞、因果、モデル一般化の主張はしない。
- 入力／モデルファイル／コード／依存／GPU／ホストRAM／抽出設定／所要時間／失敗・試行数を記録。モデル重みとvenvはZIPに含めない。

## 3. 技術的な予想と判定

1. 2文書完了後にworkerを終了し、累積checkpoint ZIPを作る。別フォルダへ復元し、原観測ハッシュが一致した状態から新プロセスで残り2文書を実行できる。
2. 完了後の再呼出しはforward 0回で、4件の原観測を変更しない。
3. 全4件・16点の原観測と派生物が揃い、別プロセスでSVD結果を照合できる。V1は独立にGram行列の固有値からも検査する。数値許容差はspec.jsonで固定する。
4. 一時コピーの欠落・破損・別設定・ZIP重複メンバーを拒否する。元の観測は破壊しない。
5. ユーザーから戻った最終ZIPをこちらで再読込・再集計して一致する。

1〜4の成功は `COLAB_VERIFIED_AWAITING_LOCAL_RECEIPT`。5が終わるまで往復試験の完了とはしない。1は同一VM内での別プロセス・ZIP復元試験であり、VM強制消失やブラウザ転送成功の実証とは異なる。失敗は理由付きで残し、低いR1/V1を失敗条件にしない。

## 4. 枠と停止

- A100／RTX PRO 6000 Blackwell候補。実際のGPU・VRAM・RAMを別々に測定。Python 3.11〜3.13/Linux x86_64、CUDA対応PyTorchを要求。
- 固定する主要依存：PyTorch 2.8.0+cu128、Transformers 4.57.6、NumPy 2.2.6、tokenizers 0.22.2、safetensors 0.7.0、huggingface-hub 0.36.0、隔離環境のpip 25.2。全インストール済み依存も記録する。推移依存全wheelの事前固定ではない。
- セル1回の処理上限40分（環境構築上限20分を含む）、終了時回収に最大2分を別枠で確保。ブラウザへの転送時間とユーザー操作時間は別。自動的な科学条件の変更・上限拡張は行わない。
- 初期空きディスク15 GiB以上。原観測・ログ等の展開量128 MiB以下、各ZIP64 MiB未満。P0は小さいため累積ZIPとし、分割shardは不要。
- 見積り：初回10〜20分程度、環境・モデルのキャッシュがあれば短縮する可能性。計測済みの性能保証ではない。checkpoint約6〜8 MB、最終約12〜16 MB、合計約18〜24 MBを想定。
- 原隠れ状態だけで `4*256*768*4*4=12,582,912 bytes`。基底・score・特徴・ログを加える。最終ZIPはcheckpoint以前の観測も含むので、正常完了後の共有は最終ZIP1本でよい。
- エラー時は可能な限り診断ZIPを返す。原因を保存し、CPUでの代替実験、精度変更、別モデル、P1以降の実行には進まない。

## 5. 復旧と版管理

同じ生きたruntimeでは同じセルを再実行して継続する。runtime喪失後は手元の最新の累積ZIPをアップロードし、同じ版のセルの`RESTORE_ZIP`で指定する。既存原観測は再利用前にハッシュ・設定を検査する。未完了の作業は記録を保持して新attemptにする。GPUが変わる場合は混在を避けるため同じrunへの継続を拒否し、報告を返す。

原稿・旧コード・旧データ・参考サンプルは変更しない。本P0の修正が観測取得後に必要ならv2として並置する。仕様・閾値を結果の後で書き換えない。
