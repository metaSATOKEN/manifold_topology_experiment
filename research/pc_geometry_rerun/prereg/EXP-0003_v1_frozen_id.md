# EXP 0003 v1 固定ID比較の未使用記事での再現と同一トークン内の関連

2026-10-20。P2と探索的追加解析EDA-0001を知った上で設計する、新しい64記事での確認。ユーザー依頼は「今回のID比較モデルを固定して、まだ使ってない記事で機序を確認」「設計・事前登録・Colab用の1セルコードまで」「実行はこっち」。agentは設計・入力準備・実装・保存データによる検査を行い、新しいモデルforwardはしない。

## 1 問いと証拠の範囲

固定済みのID比較モデルに対して、8PCの追加予測とランダム8方向への優位性が新しい記事でも再現するか。さらに、**同じ記事の同じトークンIDの出現間の変動**にも追加予測が残るかを調べる。

後者では、ID固有の定数効果、同じIDに結び付く復号長・固定頻度の違いは群内中心化で消える。残った関連があれば「トークンの種類の違いだけでは説明できない、出現ごとの状態との関連」を支持できる。ただし、文脈内容、位置、その他の状態差を介入で切り分けない。**因果機構の同定、純粋な意味因子、PC専用機能の証明ではない。** 未来トークンの言語モデル性能を改善する実験でもない。

## 2 固定する比較モデル

EDA-0001のID比較の完成済み係数、標準化、ID効果、P2のPCA平均・基底、ランダム20組の基底、訓練頻度表を、float64のままコピーする。新しい記事では学習・再PCA・モデル選択・正則化調整・符号合わせ・頻度更新を一切しない。整数マスクへの変換は真偽値と同値で、浮動小数点係数を丸めない。

- 言語モデル：`openai-community/gpt2` revision `607a30d783dfa663caf39e06633721c8d4cfcd7e`。元P2のモデル・tokenizerファイルハッシュと一致を要求。
- 抽出点：第6ブロック後block06（主要）、最終LayerNorm後final_ln（副次）。
- 条件：**C1のみ**。P2訓練で先頭位置0を外して作った基底とID比較を固定する。新しい文章の入力は削らず512tokensをforwardし、予測評価は位置1〜511。C0/C4は前回の感度分析として保持し、本確認の対象範囲をC1に限定する。結果を見て条件を追加しない。
- 元の8変数：位置p、p²、p³、log1p位置、log1p復号文字数、log1p UTF-8長、P2訓練頻度によるrarity、log1p元状態ノルム。
- block06：alpha 0.1、ID縮約tau 1、PC gamma 0.0001。final_ln：alpha 0.1、tau 10、PC gamma 0.0001。ランダム各組のgammaも既存の選択値を固定する。全22モデル×2点の正確な値・出所・ハッシュは `../p3_v1/frozen_manifest.json` と内包NPZに固定。
- 22モデルは、ID基礎、ID＋8PC、ID＋ランダム8方向20組。未出IDの効果は0、その他の特徴は訓練時の変換のまま。

係数はP2訓練64記事だけで推定されたが、モデル族を採用した判断には既知のP2評価結果も使われている。その選択後の外部確認が今回の役割であり、P2を再び未見評価と呼ばない。今回の「固定」はハイパーパラメータだけでなく、係数そのものの固定を意味する。

## 3 未使用記事の選択

同じ固定WikiText-2 raw v1の元train splitを使う。revision `b08601e04326c79dfdd32d625aee71d232d685c3`、Parquet SHA-256 `e83889baabc497075506f91975be5fac0d45c5290b6b20582c8cd1e853d0c9f7`。保存済みコーパス・tokenizerだけから入力を準備し、新しいモデル出力を選択に使わない。

P1/P2と同じ記事組立・見出し除去・本文先頭8192 Unicode文字・先頭512tokens、BOS/EOS/paddingなし。短い記事、正規化タイトル重複、512token列一致を除外する。P1全64記事とP2全128記事（訓練・評価の両方）のIDを除外。P0との256token先頭一致も除外。

残りを `sha256("pcgeom-p3-20261020:" + full_article_body_sha256)`、IDの順に並べ、P1/P2全記事と採用済みP3記事に対するtoken 5-gram集合Jaccardが0.5以上の近重複を除外。最初の64記事をすべて評価用に固定する。不足時に閾値を緩めない。IDs・入力文字列・token IDs・除外理由をmanifestに保存する。

「未使用」は本研究のモデル観測と予測器調整に未使用という意味。コーパス全体の入力準備は既に行っており、GPT-2事前学習で未知とは保証しない。記事間の話題の関連も完全には排除しない。

## 4 二つの評価

### 通常の記事内評価

現在トークンを読んだ状態h_tに、`−log p(x_t|x_<t)`を対応させる。位置0はsurprisal NA、位置1〜511の511点を全22モデル共通で使う。

記事ごとに、通常のsurprisal平均周りSSTを用い、

- `A = (SSE_ID − SSE_ID+PC) / SST`
- `B = (mean_20 SSE_ID+random − SSE_ID+PC) / SST`

を計算する。負値を保持。20ランダム組から最良のものを選ばない。

### 同じ記事の同じID内の評価

記事内の位置1〜511で、同じトークンIDが2回以上出る群だけを使う。各群について、正解surprisalと各モデルの固定予測から、それぞれの群平均を引く。単発IDは除外し、群・モデルごとに異なる観測を選ばない。中心化後の予測器を学習したり、新しい記事へ配備する予測器に置き換えたりしない。

中心化した正解の二乗和をwithin SST、中心化した正解と予測の誤差二乗和をwithin SSEとし、

- `C = (within SSE_ID − within SSE_ID+PC) / within SST`
- `D = (mean_20 within SSE_ID+random − within SSE_ID+PC) / within SST`

を計算する。これは**評価統計として群内の変動を取り出す操作**。評価ラベルの群平均は採点にだけ使い、当てはめ・選択・通常の予測A/Bに戻さない。群平均を未知ラベルなしで予測できるという実用性能指標ではない。

有効群が8未満、繰り返し群に属するトークンが32未満、within SSTが0ならC/Dを理由付きNAにする。その他の低値・負値は除外しない。元P2の128記事では入力IDだけから繰り返し群トークン291〜419、群59〜99を確認した。これは分母実現性の開発資料であり、新しい64記事での結果を保証しない。

## 5 主要量と判定

主要判定はblock06/C1に固定。64記事におけるA/B/C/Dそれぞれの中央値を用いる。各量の有効記事を単位に10,000回percentile bootstrap、PCG64 seed 20261026、各98.75%区間（端点0.00625と0.99375）。4区間へのBonferroni配分で全体約95%を狙うが、有限標本での厳密な保証ではない。訓練済み予測器に条件づけた区間で、別訓練集合の変動を含めない。

| 量 | 操作的な基準 |
| --- | ---: |
| A 通常のPC増分 | 0.02 |
| B 通常のランダム優位差 | 0.01 |
| C 同一ID内のPC増分 | 0.01 |
| D 同一ID内のランダム優位差 | 0.005 |

**P3-H1：固定ID比較を超える追加予測が新記事でも残る。** A/Bの両方の区間下限が基準以上なら支持。どちらかの上限が基準未満なら反証。それ以外は不確定。

**P3-H2：同一ID内の出現ごとの変動にもPCの追加予測が残る。** C/Dに同じ規則を適用。これが支持されても因果的な機序確認済みとは表現しない。

各量の有効記事が58未満なら、その量に依存する仮説はデータ不足。全64記事の取得・全128記事点の評価検算が終わる前はPENDING。閾値は今回の操作的定義で、先行研究の普遍的境界・検出力保証ではない。P2の既知効果を見た上での設計と記す。

final_ln/C1の同じ4量、全モデルR²、正負件数、繰り返し群の分母を副次として報告。新しい主要判定を副次点へ乗り換えない。P1/P2の確認的判定、EDAの探索的結果は保持する。
